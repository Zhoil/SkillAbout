# Last30Days Integration

Hot Search 将 `/last30days` 的研究原则集成到轻量热点流水线中，但不复制其完整多平台引擎。完整协议版本以已安装的 `last30days` SKILL 为准；本文件定义 Hot Search 必须遵守的稳定子集。

## 采集与判断

- 使用确定性脚本抓取，不能只凭通用网页搜索生成结论。
- 先定义时间窗口，再按来源采集、标准化、聚类、去重和排序。
- 排名综合时效、原生互动量、来源质量和跨源印证；限制单一作者和单一来源占比。
- GitHub Star 是项目动量，不等同于社区观点；Star History weekly 榜单按其公开页面的每日更新结果采集。
- 保留原始来源 URL 和原生互动指标，不重建、猜测或伪造链接。

## 覆盖状态

- `ok` 表示来源成功且有结果，`no-results` 表示成功但没有匹配项。
- `unreachable`、`rate-limited`、`schema-drift`、`timeout`、`error` 等均表示覆盖不完整，不能写成“该平台没有讨论”。
- 部分来源失败时保留成功结果，推送中明确标注部分覆盖，不用低质量来源静默填充。

## 输出约束

- 输出先给最高信号发现，再给来源、指标和链接；不倾倒内部聚类或调试数据。
- 社区观点应来自真实帖子或评论，并清楚区分事实、观点和项目指标。
- 定时推送使用 `SKILL.md` 末尾的文本卡片格式；完整 URL 单独成行，超长消息只能按完整行截断。
- 不追加重复的 Sources/References 链接堆；正文已有来源链接即可。

## 自动化边界

- 定时任务只能读取已落盘且通过校验的推送配置，不在无人值守执行时发起对话澄清。
- `enabled=true` 与明确的 `channel` 共同构成自动推送授权；缺失或无效时必须失败关闭。
- 写操作超时后不自动重试，避免状态未知时重复发送。
- 凭据只从环境变量或受控配置加载，报告和日志不得输出 webhook URL、token 等密钥。

## 与完整 `/last30days` 的关系

当用户要求针对具体主题做深度近 30 天研究、人物/项目账号解析、跨平台评论综合或趋势发现时，应调用完整 `/last30days` 技能。Hot Search 负责固定主题的轻量热点榜单和每日推送，不声称覆盖完整协议中的所有来源与研究步骤。
